# Referencia funcional por módulo

> Referencia de la implementación observable en el repositorio, no una especificación de producto ni una garantía de preparación para producción. Las rutas API directas corresponden a FastAPI; cuando existe un alias `/api/*`, el navegador lo envía a Next.js y este lo reescribe al prefijo directo. Consulte [arquitectura actual](./ARCHITECTURE_CURRENT.md) para la topología.

Las pruebas listadas abajo son las existentes identificadas en el repositorio, no una afirmación de que se hayan ejecutado en cada cambio. Consulte [`TESTING.md`](../TESTING.md) para comandos y requisitos completos.

| Módulo | Pruebas existentes | No queda demostrado por esas pruebas |
| --- | --- | --- |
| Auth/cuentas | `services/api-unified/tests/test_app.py`: health/rutas y registro-login-`me`; pruebas de navegador de auth/sesión en `scripts/platform.browser.test.mjs`. | Flujo real de entrega de correo Resend; seguridad operacional de secretos, expiración/revocación bajo despliegue real o administración UI completa. |
| Proveedores | CRUD API en `services/api-unified/tests/test_app.py`; interacciones de UI en `scripts/platform.browser.test.mjs`. | Persistencia/consistencia entre réplicas o operación con una base compartida de producción. |
| Incidencias/analizador | CRUD y summary básicos en `services/api-unified/tests/test_app.py`; flujos de UI/proxy sintético en `scripts/platform.browser.test.mjs` y `scripts/platform-proxy.test.mjs`; mapeo y deduplicación del seed en `scripts/tests/test_seed_incidents.py`. | Todas las ramas de permisos, concurrencia/multi-proceso en JSON, grandes cargas sostenidas o pipelines externos de negocio. |
| Inventario | Contratos del cliente y cálculo de estado en `lib/inventory-api.test.ts` y `lib/inventory.test.ts`; contrato sintético de UI en `scripts/platform.browser.test.mjs`; API de prueba usa SQLite temporal en `services/api-unified/tests/test_app.py` para registro de rutas. | Conexión/escrituras contra Supabase/PostgreSQL real, despliegue de esquema/migraciones, bloqueo de fila o carreras concurrentes en PostgreSQL. |
| Talento | Rechazo de rol `user` por API en `services/api-unified/tests/test_app.py`; contrato sintético en `scripts/platform.browser.test.mjs`. | Llamadas reales al tracker, disponibilidad, datos no sintéticos, ni escritura persistente local. |
| Reposición | Unittest CLI en `.agents/skills/replenishment-planner/tests/test_recommend_replenishment.py` para resultados, validación de CSV, errores y seguridad de archivos de salida. | Calidad de los datos de entrada o validez comercial de la recomendación; no hay integración con inventario/API ni compra automática. |

Las pruebas de navegador y proxy que sustituyen respuestas upstream son pruebas de contrato/simulación. La suite FastAPI usa archivos temporales y SQLite, no la instancia Supabase real. Las pruebas de launcher validan el ciclo de vida local solo si se activa explícitamente `BACKOFFICE_LIFECYCLE=1`; no verifican operación Docker de larga duración ni preparación para producción.

## Configuración operacional relacionada

- `JWT_SECRET` es obligatorio para que la API complete su startup.
- `DATABASE_URL` es opcional para el arranque de la API si no se usa inventario; sí es necesaria para inicializar y operar el módulo de inventario. Compose requiere que exista el archivo `.env` por su declaración `env_file`.
- `FRONTEND_URL` y `RESEND_API_KEY` afectan al envío de recuperación de contraseña; sin API key no se envía email. `TRACKER_API_URL` selecciona el upstream de talento; si no se configura se usa el playground externo.
- La composición de servicios, los secretos y respaldos se describen en [despliegue Docker](./DOCKER_DEPLOYMENT.md). Compose es una topología de ejemplo y no certifica readiness para producción.
